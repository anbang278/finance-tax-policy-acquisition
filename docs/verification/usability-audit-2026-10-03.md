# 项目完成度与小白采集体验验收

验收日期：2026-10-03（Asia/Taipei）。代码基线：`8c31e1a90133f0f26742b6737d8dd5eaf50d0438`，包版本 `0.1.0`。开始时 Git 工作区干净。

**结论：工程基线 PASS；真实采集完整性 PARTIAL；“小白简单说话完成采集，失败时知道缺什么、为什么、怎样补齐”的目标验收 FAIL。**

已有安装、采集、存证和只读查询能力可用，两来源在本机均真实访问成功。但短日期范围仍扫描完整历史栏目；附件失败后的普通续跑不能补齐，且可能返回 COMPLETED；失败诊断未完整持久化，也缺少面向普通用户的恢复建议。不能据自动测试全绿认定核心体验已经完成。

本轮仅新增验收文档。没有修改产品代码、现有可信测试、既有业务资料或复核状态，没有提交、推送、宿主插件安装或常驻部署。用户确认每批结束后说“继续”；本轮真实采集在首批结束后停止，没有自动续跑。续跑与故障恢复通过隔离数据及受控替身验证。

## 3. 关键缺陷与最小改进顺序

共确认 **8 项缺陷：4 项 P1、4 项 P2**。没有发现 P0。严重度依据是本次目标，P1 表示明显阻碍完成、恢复或范围控制；P2 表示语义、协作或证据问题。完整复现、期望、实际和验证建议见[缺陷清单](usability-audit-2026-10-03/defects.md)。

| ID | 严重度 | 问题 | 最小建议 |
|---|---|---|---|
| D-01 | P1 | 附件失败后普通续跑不补齐，可能变成 COMPLETED | 把缺失附件纳入可恢复工作项；结果必须持续报告未补齐附件，避免队列 SAVED 掩盖缺失 |
| D-02 | P1 | 短时间区间也扫描全部历史栏目 | 优先使用可信日期筛选；没有来源筛选时，只有核实排序和日期语义后才能安全收束，不能简单遇到旧日期就停止 |
| D-03 | P1 | 失败具体原因丢失、页面没有可操作建议 | 持久化脱敏原因、状态码、失败阶段/URL；按失败类别生成小白可理解的缺失与恢复说明 |
| D-04 | P1 | JSON 范围字段错写后静默扩大来源 | 严格拒绝未知业务字段；把拼写错误交回 Agent 修正，不静默使用默认范围 |
| D-05 | P2 | REJECT 保存为 quarantined | 区分 REJECT、UNCERTAIN、PASS 的状态映射并补行为回归 |
| D-06 | P2 | Controller 与 Repair 对预算续跑的约定冲突 | 统一为“每批停止，等待用户继续”；区分修复门禁内首次验证续跑与后续普通批次 |
| D-07 | P2 | CLI search 可修正旧任务状态、写审计 | 普通检索走只读入口；残留任务修正留给明确写操作 |
| D-08 | P2 | 财政部分页证据都记为栏目首页 URL | 保存每页实际请求及最终 URL，确保列表原件可定位到准确页面 |

名称别称、错别字、多任务“继续”的可靠识别尚缺独立对话证据。应先建立[自然语言用例](usability-audit-2026-10-03/cases.md)的真实模型评测，再判断是否需要别称表或额外提示；本轮不宣称已经观察到错误名称映射。
